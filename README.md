# Crypto Deep Research

Глубокие крипто-исследования **через Kilo CLI**, без отдельного фреймворка и привязки к провайдеру. Координатор разбирает вопрос, собирает первичные и независимые источники, распределяет решающие задачи и закрывает пробелы; critic проверяет достаточность ответа. Подробный отчёт на русском: ответ, доказательства, экономика, сравнения, контраргументы, обоснованные сценарии, риски и источники.

## Запуск

Нужны Kilo CLI и Python 3.11+ на Linux. Python-зависимостей нет. Авторизацию и модель настройте в Kilo; ключи модельных провайдеров этому проекту не нужны.

Из корня проекта создайте локальный `.env` по шаблону `env.example`. Все поля необязательны. Инструменты проекта читают переменные окружения; для гарантированной загрузки `.env` экспортируйте его из доверенного локального файла перед запуском Kilo.

```bash
set -a
. ./.env
set +a
kilo "$PWD"
```

В Kilo:

```text
/research Variational Omni: экономика, статус VAR, value capture, риски и сценарии на 6–12 месяцев
/research-check artifacts/runs/<run-id>
```

Оформленные исследования находятся в **`reports/<проект>-<дата>.md`**: вывод, оглавление, таблицы, расчёты, риски и источники. Полнота ответа указывается отдельно; неполная оценка не называется полным исследованием. Только Markdown, без служебных JSON/логов. `reports/`, артефакты и `.env` исключены из Git.

Экспорт — чистый Markdown без HTML/CSS: краткий вывод, ясные заголовки, компактные таблицы и источники по названиям **только в конце**, без числовых ссылок в абзацах. Цвета определяет тема просмотрщика. Служебные сводки, машинные ID и списки входов расчётов остаются в архиве; формулы, результаты, даты и существенные оговорки — в исследовании. Переоформление не проверяет заново финансовые данные и не создаёт оценку из неподтверждённых цифр.

Audit trail остаётся в `artifacts/runs/<run-id>/`: исходный `report.md`, результаты веток (если инструменты позволили их записать), claims, evidence, метрики и provenance. Публикация выполняется после финальной проверки: `python3 -m crypto_research publish artifacts/runs/<run-id>` (MCP: `{"args":["publish","RUN"]}`). Она повторяет проверку, не меняет архив и не делает запросов. На проект и дату используется один файл: новая проверенная публикация атомарно обновляет его, без хеша в имени; повтор неизменённой версии не переписывает файл. Исходные материалы отдельных исследований остаются в своих runs.

Прежние хеш-копии того же проекта и даты очищаются только после проверки хеша содержимого и признаков созданного издателем файла. Ручные изменения и символические ссылки не удаляются; результат содержит `removed_legacy_reports` и `cleanup_warnings`.

## Переменные `.env`

| Переменная | Для чего | Обязательна |
| --- | --- | --- |
| `COINGECKO_DEMO_API_KEY` | Бесплатный Demo-ключ для локального CoinGecko REST адаптера: [получить](https://www.coingecko.com/en/api) | Нет |
| `CR_RPC_URL` | HTTPS RPC нужной EVM-сети, при необходимости с ключом RPC-провайдера. Сеть должна соответствовать проекту | Только для RPC-запросов |

`init` автоматически проверяет все переменные из `env.example` и возвращает безопасную сводку `preflight`, также сохранённую в `run.json`. Она доступна агентам через `status`: наличие ключа, базовая корректность формата, наличие адаптера — без значений секретов. Все ключи необязательны; отсутствие дополнительных ключей не блокирует публичные источники. Отдельная проверка без создания run: `python3 -m crypto_research preflight` (MCP: `{"args":["preflight"]}`). Проверка локальная: без DNS/API-запросов, проверки авторизации, квот или расхода кредитов.

DefiLlama REST и официальные публичные страницы работают без ключей. Для подключённых keyless Context7/CoinGecko/Etherscan MCP токены не нужны. Ключи остальных сервисов помечаются `not_integrated`: наличие переменной не подключает API/MCP и не разрешает платные вызовы. Kilo запрещает ссылки на env в заголовках проектного MCP; авторизация MCP настраивается отдельно. Не добавляйте реальные секреты в `env.example` или `kilo.json`.

## MCP И Разработка

В `kilo.json` подключены:

| MCP | Назначение |
| --- | --- |
| `crypto_evidence` | Основной сбор источников, наблюдения, расчёты и локальный аудит с общим бюджетом |
| [Context7](https://context7.com/docs/resources/all-clients) | Документация библиотек и API для разработки; разрешён автоматически |
| [CoinGecko](https://docs.coingecko.com/docs/mcp-server) | Официальный keyless MCP: рыночные данные и документация; вызовы требуют подтверждения |
| [Etherscan](https://docs.etherscan.io/build-with-ai/mcp.md) | Официальный keyless MCP: контракты, ABI, транзакции и логи; вызовы требуют подтверждения |

По умолчанию выбран **`crypto-research`**: обычный вопрос или `/research` означает глубокое исследование. Для разработки переключайтесь на **`crypto-code`**; он использует Context7 и сверяет примеры с установленными версиями. Защита секретов, границы исследовательских артефактов и подтверждения внешних crypto MCP сохранены. После изменения конфигурации перезапустите Kilo: уже работающий MCP-процесс может показывать старые команды. Подключения проверяются через `kilo mcp list --pure`.

Основной `/research` собирает данные через `crypto_evidence`, чтобы сохранять доказательства и соблюдать лимит. Внешние crypto MCP доступны дополнительно, но их прямые вызовы не учитываются в этом бюджете и автоматически не попадают в evidence bundle; они не используются для обхода ограничений. Бесплатные сервисы имеют квоты и неполное покрытие. Платные DefiLlama MCP и Dune MCP не подключены.

## Проверка И Ограничения

HTTPS-соединение использует проверенный публичный IP без повторного DNS-разрешения; TLS проверяет исходное имя хоста. Неявные системные прокси отключены, чтобы они не обходили проверку адреса. Проверки сети тестируются без реальных запросов; это не гарантия доступности API.

```bash
python3 -m unittest discover -s tests -v
kilo config check --pure
```

Глубокий профиль по умолчанию: до **96 HTTP-запросов и 60 минут сбора**, включая ошибки/редиректы; пользовательские меньшие лимиты сохраняются. `--profile quick` (24/15) — только для явно запрошенного быстрого обзора. Это не лимит токенов/времени модели и не квота страниц: цель — полезные независимые свидетельства и закрытие решающих вопросов. Новые runs требуют `coverage.json` с вопросами, источниками по владельцам, важными ссылками, основаниями оценки и verdict критика. `check --final` возвращает отдельно `ok` (артефакты) и `quality` (согласованность заявленного покрытия); ни то ни другое не доказывает истину или инвестиционное качество. Пробелы/произвольная чувствительность означают частичный ответ. Без независимой второй модельной семьи сохраняется предупреждение. Provider fallback и мониторинг не реализованы.

`search RUN QUERY` сохраняет бесплатную публичную HTML-выдачу DuckDuckGo в общем бюджете; это поиск ссылок, не проверенных фактов. Ключ не нужен; HTML может меняться/блокироваться — это ограничение доступа, не отсутствие данных. `inspect RUN EV --links` извлекает ссылки из сохранённой страницы без сети, `--query` ищет фрагменты/фильтрует JSON. Оригиналы необходимо читать отдельно; `discover` — только справочники CoinGecko/DefiLlama. `observe --quote --value` поддерживает числовые литералы, `3,000,000` и zero..twenty. DNS, блокирующее чтение и очередь MCP не гарантируют строгий wall-time. Если apply_patch у ветки отсутствует, она возвращает полные findings без файла; права не расширяются.
